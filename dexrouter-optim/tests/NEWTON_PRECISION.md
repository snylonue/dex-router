# 精确局部消元与价格分辨率：不删池的后续诊断

> 实现更新：这些结论已落实为 [精确消元和两字价格 Newton](<NEWTON_IMPROVEMENTS.md>)。
> 本文保留此前离线诊断及其数值结论；文中的“未改生产”描述的是诊断阶段。

## 核心结论

1. 区域线性系统可以通过正权 Schur/Kron 消元变得很好解；这不需要删经济池。
2. 当前严格停滞不是主要由报价或梯度求和误差造成，而是价格格点、费用区域与
   单调目标下降要求的组合。
3. **已经找到通过原完整严格经济验收的 f64 价格。不能宣称 f64 没有解。**
   但该候选的原始目标增加约 2.10e-19，不能冒充满足原 Armijo 的迭代。
4. 高精度连续候选保持原目标下降，保留额外价格位后通过严格经济检查；简单
   舍入回 f64 却失败。因此若保留现有单调目标契约，优先研究保留价格低位，
   而不是全市场换高精度报价或继续盲删池。

完整数据与位精确价格见证在 [机器结果](<newton_precision_results.json>)。
本次未修改生产求解器、池集合、数学边界、经济容差、Armijo 或状态分类。
所有探测在优化器之外；这不是 native Newton 已成功或速度提升的宣称。

## 1. 精确消元：剩余核心真的不病态

只分析 USDC 接地曲率块。相对增量 y=dp/p 的区域模型为

    A y = -diag(p) gradient.

聚合同对边，以正电导 star-mesh 形式消元：删除线性系统中的节点 i 时，对其
邻居 j,k 增加 w_ij*w_ik/sum(w_i*)，并传递右端项；最后回代恢复所有变量。
保护 USDC、不删池的目标或净流量项。这是精确局部线性代数，不是经济筛选。

| 点 | 原维数 / Jacobi 条件数 | 只消 degree<=1 | 再消 degree<=2 |
|---|---|---|---|
| filtered initial | 36 / 126.216 | 27 / 117.980 | 9 / 117.136 |
| filtered final | 9 / 2.88681 | 7 / 2.88548 | 0，全部直接回代 |
| full initial | 97 / 553.895 | 58 / 14.0921 | 18 / 13.4858 |
| full final | 52 / 241.220 | 24 / 2.91070 | 7 / 1.85870 |
| full-strict final | 52 / 241.220 | 24 / 2.91070 | 7 / 1.85870 |

全量最终剩余 7 个自由节点是 WETH、USDT、WBTC、DAI、MKR、FRAX、ELON。
对快照真实右端项，90 位解消元并回代，与完整稠密求解的相对差及原系统相对
残差均小于 1e-60。控制还覆盖弱弹簧和有环图的消元。

限制：这是每个给定区域的无阻尼曲率块。整个自由矩阵还有零模，生产实现必须
保留实际 active/free 集、效用 grounding、阻尼及浮动分量处理，不能直接把
这个块的逆套到全空间。图会变化，初值核心是 18 维而不是一直 7 维。
本次没有实现或测量原生消元器的运行速度。

## 2. 报价误差和价格表示误差分开测

独立 MP V3 oracle 从导出的原始 binary64 参数精确构造 MP 数，不改善输入
数据本身。逐区间重新计算费用方向、区间耗尽、最优输入输出和支持值，不用
原生求解器的价格差商。所有验收仍用 1e-8 相对经济容差，严格样本绝对容差
1e-8，真实 turnover 和数学边界；不是把更宽松检查套到新点。

将误差分为：

- 报价误差：精确累加原生每池交易量，减去独立 MP 交易量；
- 求和误差：原生梯度，减去精确累加的原生每池交易量；
- 价格舍入：同一 MP 连续候选保留／舍入不同位数，保持 MP oracle 不变。

full-strict 旧点的最大报价误差仅为允许残差的 **1.8261e-8 倍**，
最大求和误差约 **5.78e-9 倍**，而实际 KKT 比率是 48.51。
所以只提高报价／求和精度不足以解释或消除此处的停滞。

| full-strict 实验 | 全市场最大 KKT 比率 |
|---|---:|
| 原生 f64 价格 + 原生报价 | 48.51167741823 |
| 同一 f64 价格 + 90 位报价 | 48.51167741828 |
| 一步 MP Newton，价格与报价都保留 MP | 0.01027414643 |
| 将该候选价格舍入回 f64，仍用 MP 报价 | 117.2389747900 |
| 舍入候选 + 原生报价，位精确重放 | 117.2389747900 |

连续一步的真实 MP 目标差约 -1.7136e-22，满足原下降方向和 Armijo；这是
优化器外的诊断，不是更改原生状态。最差方向的 wstETH 单价格一 ULP 对应
约 **293.63 倍**允许残差，邻点极易越过所需残差。

对同一连续候选逐位舍入，有如下控制。这里是**有效二进制位**，不是存储位；
f64 有 53 位有效精度。

| 价格有效位 | KKT 比率 |
|---:|---:|
| 53 | 117.239 |
| 56 | 9.71648 |
| 60 | 1.17765 |
| 64 | 0.0910328 |
| 80 | 0.0102741 |
| 106 | 0.0102741 |

用两个 f64 存 hi/lo，再由 MP oracle 使用它们的精确和，结果同样为
0.0102741。说明不必因这项证据而把所有运算升级为 90 位；应先保留价格低位。
这不是“至少需要 64 位才有解”的证明：下一节给出了另一组 53 位可用价格。
原生 V3 报价 API 目前也还不能直接消费 hi/lo，本次没有伪称已实现。

## 3. f64 可用点确实存在，但单调下降与残差目标会冲突

在 MP 连续候选的邻近格点上，对**全部 181 个原自由价格**做有界整数诊断。
用当前区域 Jacobian 预测 KKT，同时对全部池加入价格比 cell 约束，避免跨越
tick 或费用带后仍套旧 Hessian。每个候选最后用全部 387 个原生池独立重放。

| 诊断 | 线性预测 | 原生真实 KKT | 原始目标变化 |
|---|---:|---:|---:|
| 不限制区域，+/-512 ULP | 0.93964 | 8.44257，拒绝 | +4.3924e-19 |
| 同区域，+/-32 ULP | 2.48919 | 2.48919，拒绝 | +5.9281e-21 |
| 同区域，+/-512 ULP | 0.93964 | **0.93964，通过** | **+2.10175e-19** |

这给出了两个重要反控制：

- 无区域约束的线性模型会假报成功；不能仅用它宣称找到可验收价格。
- 真实可验收的 f64 点存在，但这个点需要极小的目标上升。相对总目标约为
  1.2e-23，经济上非常小，仍然不满足现有单调 Armijo，不能默默接受。

又对 WETH/wstETH 格点做了条件下界检查：在当前 cell、全部价格 +/-512 ULP
内，其他零曲率 wstETH 池交易量不变时，枚举可能满足 wstETH 严格残差的
相邻浮点价格对。利用其余池的凸性、USDC/WETH 池的精确 Taylor 余项，得到
目标差的数值下界约 **+3.3261e-21**；线性项最坏预算约 1.7447e-23。
这与“当前区域内严格残差需要上坡”一致。它是有范围、有 cell 前提、经
90/110 位复核的数值下界，不是区间算术证明，也不排除别的区域／更远价格。

## 4. 费用区域变化也是实际问题，不能只看旧点谱

filtered 是必要正控制：原 f64 点本来已可用，KKT=0.6202；MP 连续候选可降到
1.96e-14，简单 f64 舍入却得到 130.77。既然原点本身可用，显然不能从
“最近舍入失败”推导“f64 无可用价格”。

MP Newton 必须动态重建曲率图并做完整目标 Armijo。filtered 的中间模型维数
从 9 到 13 再到 19；中间 KKT 可先增大到 147、8.32，目标仍下降，最后才降。
固定旧 active 集的 Newton 会漏掉新激活的大池。消元解决的是当次线性模型，
不会替代区域管理和全目标线搜索。

## 5. 重放中发现的另一项价格精度陷阱

当前构建的普通十进制 JSON 路径会把部分价格解码成相邻浮点数；最终严格
格点候选有 27 个价格发生一 ULP 差异。若直接用它重放，会错误得到约 292.64
的残差，而不是 0.93964。

因此诊断使用 16 位 hex 的原始 binary64 位模式，重建全部 64 位；保留普通
解析路径的 mismatch 计数作控制，并逐点断言原生与 MP KKT 一致。新增普通
回归检查最小次正规数、1、其相邻数和最大有限值的位精确传输。本次没有
改变生产 serde 特性、重新解释 fixture，或把错误解析当成求解器报价误差。

## 6. 工程方向

优先拆成两个独立实验，不能把“求解更快”和“严格验收更好”混为一谈：

1. **局部精确消元 + 小核求解 + 回代**。必须保留原 HVP、阻尼、边界和所有池，
   公平测量构建成本、FG/HVP 和端到端时间。
2. **中心化仿射价格 hi+lo**。避免在报价前就把 base+correction 舍入成一个 f64；
   保留低位穿过 SqrtPriceTarget、目标差、边界和最终独立验价。仿射坐标保留
   原凸性；只有最终报告 hi 而丢掉 lo 仍会验收失败，需要明确结果/API 契约。

另一个选项是显式、可验证的最终残差修复及目标增量预算，但这改变单调接受
契约，必须单独设计和标识，不能叫原 Armijo 收敛。本次不做该变更。
